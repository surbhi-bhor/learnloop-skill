# Practice and evidence

Read this reference for the `practice` command. The goal is retrieval,
explanation, application, debugging, and then interview practice. A note is a
reference, not proof that a skill has been applied.

## Practice ladder

Choose the next rung that fits the topic and learner's target role:

1. **Recall:** ask for a definition, mechanism, or key distinction before
   showing the answer.
2. **Explain:** ask the learner to explain why the mechanism works and when it
   would fail.
3. **Apply:** give realistic, small input data and ask for a solution.
4. **Debug:** present a broken pipeline or model, with symptoms and a minimal
   set of useful evidence.
5. **Interview:** ask a role-appropriate question and request a concise
   reasoning path, trade-offs, and ownership where relevant.

Use a production-style scenario when it tests an actual failure mode. Mark
hypothetical details. Mix previously learned material only when the user has
practiced it before; otherwise keep the first attempt focused.

## Teach-back grading

The same model that taught the topic grades the answer, which makes grading
lenient: it knows what the learner meant and fills gaps for them. These rules
counter that.

Before asking, define two or three key points required for a pass and write
them to the Practice Bank `Key points` property, so the bar is fixed before the
learner answers. Ask with the note hidden: do not show or quote the note in the
question.

Grade each key point separately. For each one, quote the learner's own
sentence that states it. If no sentence states it, the point is not met, even
if the learner probably knows it. A point is met only when the learner said it,
not when it follows from what they said, and repeating words from the question
does not count. When unsure, grade Needs work: a missed pass costs one more
review, while a false pass closes a weak spot that is still open.

Show the learner the quote-per-point table with the result, so they can dispute
a grade. Then apply:

- **Pass:** all required points are correct, with no material contradiction.
- **Needs work:** some points are correct, but a required point is missing or
  unclear.
- **Fail:** the explanation contains a material misconception or misses most
  required points.

State the missing or incorrect point and give one targeted follow-up. Do not
count hints as understanding. Ask the learner to restate or apply the idea
before marking the attempt passed. Record both the rubric and result so the
learner can see why an attempt passed. Keep the weak spot open until a delayed
teach-back passes; an immediate retry does not close it.

A delayed teach-back counts only if it happens at least one day after the
weak spot was flagged and the learner has not reread the note in that attempt.

## Project ideas and evidence

Offer a small project that exercises the target skill and can extend work the
learner has actually described. Do not assume a portfolio project exists or
invent its impact. Protect private work data; use synthetic or redacted samples
unless the learner chooses otherwise.

Draft resume bullets and STAR stories from user-provided facts only. Use
brackets for missing measurements, such as `[measured reduction]`, and leave
them blank until the learner supplies real results. Link evidence to the
project or practice item that supports it. Label drafts as drafts until the
learner confirms the details.
